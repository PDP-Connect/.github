# Contributing

Thanks for your interest in contributing. We welcome fixes, features, docs, and
connectors.

To get started, each repo's `README` lists how to install, build, and run its
checks. Run those before opening a pull request.

## Pull requests

- Keep it focused: one change, one purpose.
- Use a draft PR while you iterate; mark it ready when it is.
- We squash-merge, so your branch history stays yours.
- Sign off your commits (`git commit -s`); a bot enforces the DCO.

## AI assistance

Building with AI is welcome. If AI helped meaningfully, add `Assisted-by: AI` to
each assisted commit and as a standalone line in the pull request description; a
local hook can add the commit trailer for you
(`.github/hooks/prepare-commit-msg`). It is vendor-neutral and sits alongside
your sign-off. We review contributions on whether they are good, not how they
were made.

## Security

Report vulnerabilities privately, not in a public issue. See `SECURITY.md`.

## Code of Conduct

By participating you agree to the [Code of Conduct](CODE_OF_CONDUCT.md).
